# 자동 진단 규칙 (초안, 11-08)

숫자만 보고 판정할 수 있는 규칙이에요. `analyze.py`가 이 파일의 규칙대로 판정하고 정해진 문장에 숫자를 채워요(토큰 0).
지금은 모두 "후보"예요. 사용자가 확인하면 "사용 중"으로 바꿔요.

## 글은 처음 만든 그대로 둬요 (11-08 사용자가 정함)
- 리포트의 레이아웃, 디자인, 숫자 그래프·표는 최신 형태로 바뀌어요.
- 자동 진단 문장과 피드백 글은 처음 만든 그대로 둬요. 규칙이 바뀌어도 예전 판의 문장은 다시 만들지 않아요.
- 자동 진단 문장은 처음 만들 때 `feedback/<경기ID>.auto.json`에 저장하고, 이 파일이 있으면 다시 만들지 않아요. 어떤 규칙 버전으로 만들었는지는 적지 않아요.
- 예외: 계산 버그로 문장이 틀렸으면 그 판의 파일만 지우고 다시 만들어요.
- 여러 판을 모아 비교할 때는 진단 문장을 세지 않고, 판마다 남은 숫자에 같은 기준을 다시 적용해서 계산해요.

## 칸 세 가지
- **지적:** 고칠 점으로 보여 줘요.
- **사실:** 지적하지 않고 있었던 일만 적어요.
- **확인 필요:** 규칙에는 걸렸지만 해석이 갈려요. 피드백을 쓸 때 Claude가 보고 판단해요.

## 기준선
- "기준 하위 25%"는 에메랄드~다이아 같은 챔피언 기준 데이터(`benchmarks/<챔피언>.json`)의 p25예요(시간 지표는 p75보다 늦을 때). 숫자로 박지 않아서 기준 데이터를 다시 모으면 따라 바뀌어요.
- 기준 데이터가 없는 챔피언(지금은 카이사, 아리)은 기준 규칙을 건너뛰고, 고정 기준 규칙만 써요.

## 원인이 겹칠 때
1. 원인은 두 단계예요: ① 죽음(lane-death, death-streak, death-total) ② CS(lane-cs-sup, cs-game). 죽음 규칙끼리는 서로 다른 지표라 함께 걸리면 모두 보여 줘요.
2. "결과" 규칙(lane-gold, core1, core2)은 원인 규칙이 하나라도 걸리면 따로 지적하지 않아요. 가장 앞 원인의 문장 뒤에 "이 때문에 ~도 기준보다 낮았어요"로 한 줄만 붙여요.
3. 원인 규칙이 하나도 안 걸렸을 때만 결과 규칙을 지적으로 보여 줘요.
4. 10/15분 CS와 15분 CS 차이는 따로 지적하지 않아요. 서폿이 없던 시간이 섞여서, CS는 lane-cs-sup와 cs-game으로만 봐요.

## 지금 판에 적용해 보면
- **자야 판:** 지적은 "게임 전체 분당 CS 6.8개(목표 7개)" 하나예요. 서폿이 있을 때 분당 CS(8.2개)는 기준 중간이라 지적하지 않고, 서폿이 없던 3~8분, 11~13분의 분당 CS 5.9개는 사실로만 적어요.
- **징크스 판:** 지적은 "14분 전 4번 죽음"(이 때문에 15분 골드 차이와 첫 코어 시간도 낮았다고 한 줄), "3:46~5:32에 2번, 13:10~17:54에 5번 연달아 죽음", "게임 전체 분당 CS 4.9개"예요. 서폿이 바텀에 있던 시간이 2분뿐이라 lane-cs-sup는 건너뛰어요. 확인 필요는 혼자 죽은 2번(5:32, 15:28)과 분당 피해예요. 원래 기준 하위 25%에 걸린 지표는 13개였어요.

## 규칙을 계속 고치는 방법
1. **기준선은 숫자로 박지 않아요.** "기준 하위 25%"처럼 적어서, 기준 데이터를 다시 모으면 기준선도 따라 바뀌어요.
2. **반박을 기록해요.** 사용자가 자동 진단에 반박하면(예: "이건 서폿 탓") 반박 횟수를 올리고 이유를 적어요. 같은 반박이 2번 넘으면 조건을 고치거나 보류해요.
3. **판단을 자동 규칙으로 옮겨요.** Claude가 여러 판에서 같은 모양의 판단을 반복하면 자동 규칙 후보로 올려요. 사용자가 확인하면 "사용 중"으로 바꿔요. 이렇게 하면 판단에 드는 토큰이 점점 줄어요.
4. **패치가 바뀌면** 챔피언·아이템에 관련된 규칙에 "확인 필요"를 붙여요.
5. **10판마다 점검해요.** 스크립트가 규칙별로 몇 번 걸렸는지, 반박이 몇 번 있었는지를 뽑아요. 그걸 보고 너무 자주 걸리는 규칙, 한 번도 안 걸리는 규칙을 정리해요.
6. **효과 확인은 20~30판이 쌓인 뒤에 해요.** 그 전에는 판 수가 적어서 "이 규칙을 지킨 판이 더 이겼다" 같은 판단을 하지 않아요.
7. 바뀐 내용은 git 기록에 남아요. 규칙을 고칠 때 날짜와 이유를 한 줄 적어요.
